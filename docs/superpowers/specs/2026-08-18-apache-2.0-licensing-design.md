# Apache-2.0 Licensing Design

**Date:** 2026-08-18
**Repository:** `jacksoncai001/review-workflow-codex`
**Decision owner:** `jacksoncai001`

## Goal

Turn the public repository into a permissively licensed open-source project so
individuals and organizations may use, copy, modify, redistribute, sublicense,
and commercially use the project while preserving attribution, modification
notices, warranty disclaimers, and the Apache-2.0 patent terms.

## Decision

License the original project code, prompts, schemas, documentation, and
configuration under the unmodified Apache License, Version 2.0, SPDX identifier
`Apache-2.0`. Use `jacksoncai001` as the public copyright holder and 2026 as the
copyright year.

Apache-2.0 is selected instead of MIT because this integration-oriented Skill,
MCP server, and harness benefits from an explicit contributor patent grant.
GPL-3.0 is not selected because downstream modified or combined works should not
be required to use a reciprocal open-source license.

## License scope and boundaries

- The root `LICENSE` contains the complete, unmodified Apache-2.0 text.
- The license covers only material for which the repository owner or a project
  contributor can grant rights.
- Third-party packages, services, models, and external projects retain their own
  licenses and terms. Merely listing or depending on them does not relicense them.
- User manuscripts, PDFs, extracted corpora, credentials, unpublished findings,
  and generated private review workspaces remain outside this repository and
  outside the project license.
- Files carrying an explicit different license or third-party notice remain
  governed by that notice.

## Repository changes

1. Add root `LICENSE` with the official Apache-2.0 text.
2. Add root `NOTICE` containing:

   ```text
   Review Workflow Codex
   Copyright 2026 jacksoncai001
   ```

3. Add `license = "Apache-2.0"` to `[project]` in `pyproject.toml`.
4. Add an Apache-2.0 badge and license section to `README.md`; replace the
   no-license warning with the new license scope and third-party boundary.
5. Update `docs/third-party-notices.md` to distinguish project-authored material
   from dependencies governed by upstream licenses.
6. Mark the owner license decision complete in `docs/release-checklist.md`.
7. Add `CONTRIBUTING.md` stating that intentional submissions accepted for
   inclusion are licensed under Apache-2.0, consistent with section 5, unless
   explicitly designated otherwise. It also repeats the private-research-data
   boundary and points contributors to the existing test commands.

The initial release does not add boilerplate headers to every source file. The
root license, package metadata, README declaration, NOTICE, and contribution
terms provide one consistent repository-level declaration without repetitive
file churn.

## Verification

A static release-contract test will be written first and observed failing before
the license files and metadata are changed. It will require the Apache-2.0
license text, SPDX metadata, copyright notice, README declaration, contribution
terms, and removal of the no-license warning.

After implementation, run the release-contract tests, lock check, Ruff checks,
and the full pytest suite. Commit and push only after those checks pass. Finally,
verify that GitHub reports SPDX identifier `Apache-2.0` for the current commit and
that the public repository settings remain unchanged: Issues, Projects,
Discussions, and Wiki disabled; Pull Requests enabled.

## Non-goals

- No Contributor License Agreement is introduced in this release.
- No user research material is moved into the source repository.
- No third-party dependency is relicensed.
- The public support policy and its no-response-time commitment are unchanged.
